## Decision layer

**Jev is live and verified on this machine.** A key is configured (stored per-user via
`route.py --set-api-key`, not in the environment), and the wire contract was confirmed
against the real endpoint on 2026-09-20:

| Check | Result |
|---|---|
| Auth | `Authorization: Bearer <key>` — `x-api-key` is rejected (403) |
| Key format | `apikey_<id>_<secret>` — **not** `sk-...` as earlier notes assumed |
| `model` field | required; omitting it returns 422 |
| Model pin | `jev-1.13.0` accepted and **validated** (`jev-9.99.9` → 400) |
| `GET /v1/models` | lists only the `jev-latest` / `jev-preview` aliases |
| Latency | ~0.6–1.1 s for a seven-question routing fan-out |
| Cost | ~2,160 input tokens per routing decision ≈ **$0.00009** |

Note the asymmetry in the model API: concrete versions are accepted but not enumerated, so
`jev-1.13.0` cannot be discovered from `/v1/models` — it has to be read off a response.
Both `jev-latest` and `jev-preview` currently resolve to `jev-1.13.0`.

`typesafe-sdk` is still not installed, so the raw-HTTP path in `jev.py` is what actually
runs here. That path is the one now covered by the live contract tests.

Verify at any time with:

```
python scripts/probe.py --check-jev
```
